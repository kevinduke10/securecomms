- **Area:** Product / architecture / security / persistence / deployment / interaction
- **Delivery:** Implemented / partially implemented / planned
- **Source:** User requirement, accepted plan, or engineering decision; state which.
- **Supersedes / superseded by:** Link related ADRs, or omit if not applicable.

## Context

Describe the concrete requirement or problem and the constraints that matter.

## Decision

State the chosen approach and the boundaries future contributors should preserve.
Separate implemented behavior from accepted future work.

## Rationale and alternatives

Explain why this approach fits and the meaningful alternatives considered. Do not
invent a discussion or user approval that did not happen.

## Consequences

Record tradeoffs, limitations, compatibility/migration concerns, and follow-up work.

## Implementation and evidence

Link relevant code, tests, or current documentation. State what is verified and
what remains unimplemented or unverified.
